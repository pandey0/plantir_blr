# Standards Compliance — public-map

> **Ownership rule**: fix or deliberately defer a gap found here → update its row in the same change. Adding a new gap you found but aren't fixing right now is also an update — don't just leave it undiscovered.

Section-by-section audit of `apps/public-map` against [`../standards/frontend-engineering-standards.md`](../standards/frontend-engineering-standards.md), done 2026-08-10 alongside the `/v1` API adaptation work (this app's first real engineering pass since being scaffolded — see [`TECH_STACK.md`](TECH_STACK.md)'s decision log). Status per section: **✅ Compliant**, **🔧 Fixed this session**, **⏸ Deferred** (with a reason), or **N/A** (doesn't apply to this app's shape). Compare against [`STANDARDS_COMPLIANCE.md`](STANDARDS_COMPLIANCE.md) (the engine's equivalent doc) for the pattern this follows.

**Scope note**: this app is public-map only — a read-only observability dashboard, no auth, no forms, no mutations. A number of sections in the standard (forms, authentication UI, file uploads, optimistic UI) are N/A here by the app's own nature, not oversights; they'll matter for `citizen-app`/`authority-portal` when those get built.

## Summary of what actually changed this session (2026-08-10)

Centralized API layer (#10 — `lib/api.ts`, closing the actual production break this whole round was triggered by), environment variables (#28 — `NEXT_PUBLIC_API_URL`), dependency management (#34 — `npm run lint` went from completely broken to clean), plus this compliance doc and `CLAUDE.md`/`README.md` themselves (this app had zero docs before this session). Everything else in the table was either already fine, structurally N/A for a read-only single-page app, or is a real, explicitly-tracked deferral — not a silent gap. The biggest deferred items worth prioritizing next, in rough order: testing (#38), error boundaries (#36), type safety (#35), accessibility (#22).
